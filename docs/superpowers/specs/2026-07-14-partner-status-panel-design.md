# 培训合伙人审核状态面板设计

**日期**：2026-07-14  
**分支**：`0713-lzh`  
**范围**：用户中心「培训合伙人」页的审核中 / 已通过状态 UI；专用预览路由；真实页按申请状态分支  
**不在范围**：已驳回态 Figma 还原、申请表单交互改造、申请提交 / 审核 API 对接、站内消息联通  

**Figma**：https://www.figma.com/design/oH4ffDnHm2XLhgwLzXKyOw/淘课网UI?node-id=31-606  
- 审核中：`31:609`  
- 已通过：`31:608`  

---

## 1. 背景与目标

现有 `/dashboard/alliance/partner` 仅为写死的协议 + 申请表单，无法展示审核中 / 已通过结果态；Figma 已给出正式视觉（印章、水印、编号），但本地账号难切到这两种状态，需要可对照预览。

**目标**：

1. 按 Figma 还原「审核中」「已通过」两屏。  
2. 提供不依赖真实审核数据的预览 URL。  
3. 真实页按申请状态显示新面板；未申请仍显示协议表单。  
4. 两处分用同一 UI 组件，避免漂移。

---

## 2. 用户决策

| 项 | 选择 |
|----|------|
| 状态范围 | **A** — 仅「审核中」+「已通过」（驳回以后再说） |
| 预览方式 | **A** — 专用预览路由 `?status=` |
| 预览 vs 真实页 | **A** — 两者都做 |
| 实现方案 | **方案 1** — 共用状态面板 + 预览路由 + 真实页状态分支 + 适配层 mock |

---

## 3. 方案选型

| 方案 | 结论 |
|------|------|
| **共用 `PartnerStatusPanel` + `/preview?status=` + 真实页分支** | **采用** |
| 真实页加 `?previewStatus=` 强制切 | 不采用 — 与菜单真实路径易混 |
| 预览与真实两套静态页 | 不采用 — UI 易漂移 |

说明：现码无合伙人申请状态 API。本期通过 `getPartnerApplicationStatus()` 适配层（默认可返回 `none` / 可 mock）占位，接口就绪只改该层。

---

## 4. 页面结构与状态分支

外层壳保留现有用户中心卡片：顶栏「培训合伙人」+ 白底圆角内容区。

| 状态 | 内容区 |
|------|--------|
| `none`（未申请 / 无记录） | 现有协议 + 申请表单（本期不改交互） |
| `pending` | `PartnerStatusPanel` 暖黄稿 |
| `approved` | `PartnerStatusPanel` 绿稿 |
| `rejected` | 本期不接新 UI；真实页行为与 `none` 相同（仍显示表单）。类型可先保留 |

### 4.1 真实页

路径：`/dashboard/alliance/partner`（`ROUTES.UC_ALLIANCE_PARTNER`）

- 调用状态适配层；按上表分支渲染。  
- 无 mock / 无接口时默认 `none` → 仍为表单。

### 4.2 预览页

路径：

- `/dashboard/alliance/partner/preview?status=pending`  
- `/dashboard/alliance/partner/preview?status=approved`  

规则：

- 忽略真实申请数据，强制展示面板。  
- Query：`pending` | `approved`（大小写不敏感）；缺省或非法值兜底 `pending`。  
- 示例编号固定：`TPC_20260714134819240966`（与 Figma 一致）。  
- 不提交申请、不写真实状态。  
- 可复用与真实页相同的顶栏 / 白卡片壳。

## 5. 面板视觉与文案

对齐 Figma `31:609` / `31:608`。共用顶栏「培训合伙人」；内容区按状态换主题。

| | 审核中 (`pending`) | 已通过 (`approved`) |
|--|-------------------|---------------------|
| 内容区底色 | 暖黄浅底 | 薄荷绿浅底 |
| 标题 | 培训合伙人申请审核中（褐金，约 `#a46732`） | 培训合伙人申请已通过（绿，约 `#1c7b19`） |
| 分隔线 | 标题下细横线，金色系 | 绿色系 |
| 正文 | 您的申请资料已成功提交。工作人员将在1-3个工作日内完成您的审核。审核结果将通过站内消息通知您。 | 恭喜您已通过培训合伙人审核。 |
| 正文 / 编号色 | `#973c00` | `#195e0e` |
| 编号行 | `培训合伙人编号：` + 加粗编号 | 同左 |
| 水印 | 大号半透明 **TAOKE** + 标识轮廓（暖黄半透明） | 同结构，绿色半透明 |
| 印章 | 右下倾斜圆章「审批中」（金） | 右下倾斜圆章「已通过」（绿，含星环） |

实现要点：

- 印章、水印从 Figma 导出为仓库内静态资源（勿依赖临时 MCP asset URL）。  
- 相对定位叠层：标题居中偏上、正文/编号居中、印章右下、水印偏底；对齐稿面，不照搬绝对像素。  
- 本期无按钮、无二次操作；纯结果展示。

## 6. 组件与数据层

### 6.1 组件

| 模块 | 职责 |
|------|------|
| `PartnerStatusPanel` | 纯 UI；props：`status: 'pending' \| 'approved'`，`partnerCode: string` |
| 协议 + 申请表单 | 现有内容抽出或就地保留，供 `none` / 本期 `rejected` 使用 |
| `partner/page.tsx` | 真实页：读状态 → 表单或面板 |
| `partner/preview/page.tsx` | 预览：读 `?status=` → 仅面板 + 固定示例编号 |

建议落点：`frontend/src/features/...` 下合伙人相关目录（或与现联盟页同级的 feature 约定），页面文件仍在  
`frontend/src/app/[locale]/(usercenter)/dashboard/alliance/partner/`。

### 6.2 状态适配层

```
getPartnerApplicationStatus() →
  { status: 'none' | 'pending' | 'approved' | 'rejected'; partnerCode?: string }
```

- 页面不直接散落假数据。  
- 本期：无后端则默认 `none`；可用显式 mock / 环境开关将真实页切到 `pending`/`approved` 联调（预览路由不依赖此层）。  
- 以后：只改该模块对接 API；面板与路由不动。

---

## 7. 验收标准

1. 预览「审核中 / 已通过」两 URL 打开后视觉对齐 Figma（底色、标题、正文、编号、水印、印章）。  
2. 真实页在 `none` 时仍为协议表单；mock 为 `pending`/`approved` 时与预览同组件同视觉。  
3. 预览非法 query 兜底为审核中。  
4. 不引入对临时 Figma MCP 资源 URL 的运行时依赖。  
5. 本期不实现驳回专属 UI；不改造申请提交流程。
