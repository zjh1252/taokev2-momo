# 详情顶栏精简用户区设计

**日期**：2026-07-14  
**分支**：`0713-lzh`  
**范围**：`frontend` 公共站点详情页 `DetailPageHeader` 右侧用户区与搜索宽度  
**不在范围**：列表/首页双层顶栏、购物车/通知业务逻辑、用户中心页、Auth、PXB embed  

**修订关系**：修订 [`2026-07-13-detail-page-header-design.md`](./2026-07-13-detail-page-header-design.md) 中「详情页用户区 = 完整购物车/通知/登录用户区」的决策。

---

## 1. 背景与目标

详情页合并顶栏（Logo + 频道 + 搜索 + 用户区）落地后，已登录用户区过宽（购物车、通知、头像、昵称+角色、用户中心、我的主页、退出），在 `min-w-[1400px]` 等固定构图下与左侧频道导航抢宽，出现遮挡。

**目标**：

1. 详情顶栏去掉购物车与通知入口。  
2. 保留极简账号入口：头像 +「用户中心」+「退出」（未登录仍为登录/注册）。  
3. 若仍可能遮挡左侧频道字，缩短详情页搜索框；列表页搜索宽度不变。

---

## 2. 用户决策

| 项 | 选择 |
|----|------|
| 去掉范围 | **A** — 只去掉用户区中的购物车/通知相关；**保留搜索** |
| 账号入口 | **C** — 头像 +「用户中心」+「退出」；去掉昵称与「我的主页」并排展示 |
| 空间不足 | 缩短搜索框，避免遮挡左侧频道文字 |
| 实现方案 | **方案 1** — 详情专用精简用户区 + 搜索可缩；列表顶栏不动 |

---

## 3. 方案选型

| 方案 | 结论 |
|------|------|
| **DetailPageHeader 专用精简区 + SearchBar 可选收窄** | **采用** — 与列表职责分离，改动可控 |
| `HeaderUserActions` 加 `variant="detail"` | 不采用 — 单组件双身份易缠绕 |
| 仅 CSS 隐藏购物车/通知/昵称 | 不采用 — DOM 残留、难测、易漏 |

购物车/通知：详情页**不提供入口**；用户可回列表页顶栏或其它已知路径使用。

---

## 4. 顶栏结构

### 4.1 详情页（改后）

```
[Logo]  首页 专家 公开课 …   [SearchBar 可缩短]   头像 | 用户中心 | 退出
```

| 保留 | 去掉 |
|------|------|
| Logo、频道导航、SearchBar | 购物车（`CartBadge`） |
| 头像、「用户中心」、「退出」 | 通知铃（`NotificationBell`） |
| 未登录：登录 \| 注册 | 昵称、角色后缀、「我的主页」链接 |

### 4.2 列表/首页

不变：`TopNavBar` + `AppHeader`；完整 `HeaderUserActions`（含购物车、通知、完整 `UserAuthArea`）。

---

## 5. 组件设计

### 5.1 `DetailPageHeader`

**文件**：`frontend/src/components/layout/detail-page-header.tsx`

- 移除完整 `HeaderUserActions` 引用。  
- 右侧：`SearchBar`（传入收窄用 `className` 或等价 prop）+ 精简用户区（`UserAuthArea variant="compact"`）。  
- 路径切换逻辑仍由 `PublicHeader` + `isDetailPagePath` 负责，**不改路径判定**。

### 5.2 `UserAuthArea` compact 变体

**文件**：`frontend/src/components/layout/header-auth.tsx`

- 新增可选 prop：`variant?: 'default' | 'compact'`，默认 `'default'`。  
- **`default`**：现有行为（头像 + 昵称+角色 + 用户中心 + 条件「我的主页」+ 退出；未登录登录/注册）。  
- **`compact`**：  
  - 已登录：头像 +「用户中心」+「退出」（分隔符 `|` 与现样式一致）。  
  - 未登录：登录 \| 注册（与 default 相同）。  
  - **不渲染**：昵称、角色后缀、「我的主页」。  
- 登出、`ROUTES.DASHBOARD`、`useAuth` 复用现有实现，无新 API。

### 5.3 `HeaderUserActions`

- **不修改**列表行为。  
- 详情页不再挂载该组件（因详情不再展示购物车/通知）。

### 5.4 `SearchBar` 收窄

**文件**：`frontend/src/components/layout/search-bar.tsx`

- 现状：表单带 `min-w-[360px]`，易在详情单行顶栏挤压频道导航。  
- 增加可选 `className`（推荐）合并到根 `form`，由 `DetailPageHeader` 传入收窄类，例如：  
  `min-w-0 max-w-[280px] w-full`（实现时可按目视微调像素，以左侧频道完整可见为准）。  
- 列表/`AppHeader` 不传，保持原 `min-w-[360px]`。

---

## 6. 验收标准

| 场景 | 期望 |
|------|------|
| 任意详情页已登录 | 无购物车、无通知；有头像、用户中心、退出；无昵称/我的主页 |
| 任意详情页未登录 | 登录 \| 注册；无购物车/通知 |
| 详情页窄宽（含 1400px 构图） | Logo + 频道文字不被搜索遮挡；必要时搜索明显短于列表页 |
| 列表/首页 | 购物车、通知、完整用户区仍在 |

---

## 7. 测试

- 不强制新增单元测试（纯展示变体）。  
- 若已有 `isDetailPagePath` 等顶栏相关测试，回归保持通过。  
- 手工：详情（如专家详情）与列表各查已登录/未登录一眼。

---

## 8. 明确不做

- 不改购物车、通知铃的业务与组件内部逻辑。  
- 不把 compact 用户区推到列表顶栏。  
- 不做头像下拉菜单方案。  
- 不改 `isDetailPagePath` 匹配范围。
