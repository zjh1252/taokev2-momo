## §77 首页城市频道静态清理

### 目标

去掉首页城市频道里无意义的静态占位，避免「假定位 / 假筛选」误导用户。

### 改动范围

仅 `frontend/src/features/city/components/CityChannelCard.tsx`（及因此变成未使用的本地常量 / 图标 import）。

### 具体改动

1. 删除「定位：上海」整块（文案 + 固定跳转上海的链接）。
2. 删除 `FILTER_ITEMS` 整排 Tab（热门城市 / 附近城市 / 生产管理等无 handler 按钮）。
3. 保留城市卡片栅格（API `cities` + featured/small 展示逻辑、跳转 `cityChannelPath` 不变）。
4. 清理无用常量与图标 import。

### 非目标

不做定位能力、不做真实筛选 Tab；不改城市综合页、`city/[city]/opencourse`、城市数据接口。

## §73「给专家留言」后台可运营

### 目标

运营能在后台侧栏找到并处理专家留言；不再仅限超管类级 `@RequireRole(SUPER_ADMIN)`。

### 权限（Flyway **V161**）

| 项 | 值 |
|----|-----|
| permission_code | `trainer-message:manage` |
| permission_name | 专家留言管理 |
| module / action | `interaction` / `EDIT` |
| 赋权角色 | `PLATFORM_CS`、`PLATFORM_AUDITOR`（`SUPER_ADMIN` 仍全局跳过权限） |

### 后端

`AdminTrainerMessageController`：

- 去掉类级 `@RequireRole(SUPER_ADMIN)`
- 四个接口均加 `@RequirePermission("trainer-message:manage")`：列表 / 详情 / 标记已处理 / 转需求
- 业务逻辑不变

### 管理前端

- `nav-config.ts`：在「平台运营管理」下、内训课报名旁增加「专家留言」→ `/dashboard/trainer-messages`
- 列表 / 详情页与 BFF 已存在，不重做功能
- 侧栏若无按权限过滤：与报名菜单一致（有菜单入口 + 接口鉴权）

### 非目标

不改 C 端留言弹窗；不改留言表结构；本批不同步改造公开课 / 内训报名的 `SUPER_ADMIN` 限制。

## §76 公开课已选筛选 + URL + PXB

### 目标

主站公开课与内训一样：选了什么就有「已选条件」芯片；刷新 / 返回可恢复；PXB embed 也有汇总已选行。

### A. 主站芯片完整性

`OpenCourseListSection.activeChips` 覆盖侧栏全部维度，均可点叉 /「重置」：

- 已有：锁定城市、机构、分类、省市、时间快捷、自定义日期、价格
- 补齐缺口：凡侧栏能生效的条件都必须出芯片（含仅 `priceMin`/`priceMax`/`isFree`、仅日期无 label 等）
- 文案风格对齐内训「当前筛选」

### B. URL 同步（主站）

扩展 `open-course-list-url.ts` 的 parse / `syncUrl` / browser-diff，读写：

| 参数 | 含义 |
|------|------|
| `timeQuick` | 快捷段 |
| `startTimeFrom` / `startTimeTo` | 自定义日期 |
| `priceMin` / `priceMax` / `isFree` | 价格 |
| `priceLabel` / `timeQuickLabel`（可选） | 芯片展示文案，可从预设反推 |

`opencourses/page.tsx`（及城市公开课入口若走同一 Section）SSR 初始 props 带上上述 query，避免首屏与地址栏不一致。

排序 `sortBy`：若当前已写 URL 则一并持久化；未写则本批可不强制。

### C. PXB embed

在 `PxbCourseListSection`（公开课 embed）增加与主站同结构的「已选条件」汇总行（标签 + 叉 + 重置），状态仍走现有 `pxb-course-list-url`；侧栏内 `FilterChip` 可保留作点选控件，汇总行负责「一眼看到已选」。

### 非目标

不重构内训筛选框架；不改后端 list API；不做独立筛选历史存储。

## §78 内训课编号对齐老站

### 目标

内训详情页「课程编号」= 老淘课网原始课程 ID（`tk_courseinfo.id`），与老站完全一致，不用新生成展示号。

### 数据约定

迁移已保证 `courses.id = tk_courseinfo.id`。内训对外编号 **就是** `courses.id`，不加新列。

### 后端

`CourseServiceImpl` 组装公开详情时：

- **内训（非 open 类型）**：`displayCourseNo = course.getId()`，**不**走场次 `sort_order` / `tk_course.id` 逻辑
- **公开课**：保持现有 `resolveDisplayCourseNo(courseId, plans)` 不变

可选：data-trans 审计脚本抽样对比老库 `tk_courseinfo.id` 与新库 `courses.id`（仅 INTERNAL），发现漂移再单独 fixup（本批不强制跑全量纠偏）。

### 前端

`CourseHero.tsx`：

- 内训：`displayNo = course.displayCourseNo ?? course.id`（禁止另算）
- 公开课：继续 `resolveOpenCourseDisplayNo`
- 展示格式仍为纯数字文案

### 非目标

不改内训 URL 形态（仍 `/innercourses/{id}`）；不做公开课编号改造；不为内训引入 `TK-` 前缀。

### 验收

任选老站内训详情编号 N，新站对应课「课程编号」显示 N；`displayCourseNo` 与 `courses.id` 一致。
