## §71 内训课报名

### 目标

内训课详情页右侧 CTA「联系客服购买」改为「立即报名」；弹出与公开课同款报名表单；后台「平台运营管理 → 内训课报名」独立管理线索。与公开课报名、需求管理数据隔离。

### 认证

- C 端提交：`@Public`，**登录可选**
- 已登录：写入 `user_id`；未登录：`user_id` 为空仍可提交

### 数据模型

表名：`internal_course_enrollments`（Flyway **V159**）

| 列 | 类型 | 说明 |
|----|------|------|
| id | int PK AI | |
| user_id | int NULL | 登录用户，可空 |
| course_id | int NOT NULL | 内训课 ID（课程删除后记录保留） |
| real_name | varchar(50) | 真实姓名 |
| company_name | varchar(200) | 公司名称 |
| email | varchar(100) | 电子邮件 |
| company_phone | varchar(30) NULL | 公司电话 |
| mobile | varchar(20) NULL | 手机号码 |
| course_title | varchar(500) | 提交时冗余课程名 |
| status | tinyint(2) DEFAULT 0 | 0 待处理 / 1 已联系 / 2 已无效 |
| admin_remark | text NULL | 运营备注，默认空 |
| created_at / updated_at | datetime | BaseEntity |

索引：`idx_created_at`、`idx_course_id`、`idx_status`

无 `plan_id`。用户多次提交生成多条独立记录。课程删除后列表「关联课程」显示【课程已删除】（可附冗余原标题，产品要求至少显示【课程已删除】）。

### 校验（提交）

1. 真实姓名、公司名称、电子邮件必填；邮箱格式校验
2. 公司电话、手机号码至少填一项；底部文案：「提醒:电话或手机可选填一个」
3. `course_id` 必填且课程须存在且为内训类型
4. 不校验登录；不与订单/支付联动

### API

#### C 端

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/internal-course-enrollments` | `@Public` 提交报名，返回 id |

Body：`realName, companyName, email, companyPhone?, mobile?, courseId`

#### 管理端（`@RequireRole(SUPER_ADMIN)`，与公开课报名一致）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/internal-course-enrollments` | 分页列表：时间范围、keyword（课程名/课程ID）、status |
| GET | `/admin/internal-course-enrollments/{id}` | 详情 |
| PUT | `/admin/internal-course-enrollments/{id}` | 更新 status + adminRemark |
| GET | `/admin/internal-course-enrollments/export` | Excel；`ids` 可选，空则按当前筛选导出全部 |

### C 端 UI

- 抽出共享报名表单组件（字段、校验、底部提醒）；`OpenCourseEnrollDialog` 与 `InternalCourseEnrollDialog` 各包一层
- 内训弹窗只传 `courseId`（无期次）
- `CourseSidebar`：内训红色 CTA 文案改为「立即报名」，样式/尺寸/颜色不变；点击打开内训报名弹窗（不再打开客服购买对话框）
- 提交成功：toast；表单重置并关闭

### 管理端 UI

- `nav-config`「平台运营管理」增加「内训课报名」→ `/dashboard/internal-course-enrollments`
- Feature 目录镜像 `open-course-enrollments`：筛选、刷新、查看详情、编辑状态&备注、导出选中/全部
- 列表表头：ID｜提交时间｜真实姓名｜公司名称｜电子邮件｜公司电话｜手机号码｜关联内训课课程｜处理状态｜操作

### 权限

- 菜单可见性与同分组一致；接口层 `SUPER_ADMIN`

### 非目标（71）

- 不写入 `demands` / `open_course_enrollments` / `trainer_lead_messages`
- 不自动创建订单或支付
- 本期不改 UniApp

## §79 老账号密码兼容

### 目标

老站弱密码账号可正常登录；注册 / 改密 / 重置仍强制 6–32；登录不做密码格式校验；不做登录后强制改密。

### 数据

Flyway **V160**：`users` 增加 `old_user`（`TINYINT(1) NOT NULL DEFAULT 0`；Java `Boolean oldUser`；布尔列名不用 `is_` 前缀）。

回填：

```sql
UPDATE users SET old_user = 1 WHERE uc_uid IS NOT NULL;
```

- 后续 data-trans 迁入账号写入时置 `old_user = 1`
- 新注册默认 `0`
- 密码哈希原样保留，不做转换或重哈希

### 登录

- 去掉 `UsernameLoginRequest.password` 的 `@Size(min=6, max=32)`
- 登录只校验账号 + 密码哈希（及既有 UCenter 流程）；**不得**因密码长度/复杂度返回格式错误
- C 端 `LoginForm`：提交前不再用 6–32 长度拦截（可保留空密码提示）
- **禁止**登录后强制改密弹窗或拦截

### 注册 / 重置 / 修改密码

- 注册、忘记密码重置、个人中心修改密码：前后端继续 6–32
- `ResetPasswordRequest` / 改密 DTO 保留 `@Size(6–32)`
- 老用户改密/重置页展示提示：「您是历史迁移账号，原有密码可正常登录；修改密码时，请设置6‑32位字符的新密码。」
- 登录态改密：`/users/me`（或等价字段）暴露 `oldUser`，前端按需展示提示

### 非目标（79）

- 不强制老用户改密
- 不改手机验证码登录（本身无密码长度约束）
- 不改变注册 6–32 规则

## §72 专家列表「信得过」筛选与角标一致

### 根因

后端 `isTrusted=1` 按老站「优质」过滤：`is_trusted = 1 OR is_signed = 1`。  
前端「信」角标仅判断 `isTrusted === 1`，签约-only 讲师进入筛选结果但无角标。

### 修改（优质口径）

1. **前端角标**：列表卡、详情头图等「信」徽章改为 `isTrusted === 1 || isSigned === 1`
2. **后端过滤**：保持现有 OR 条件，不改为仅 `is_trusted`
3. **筛选持久化**：确认 `trustedOnly` / `isTrusted` 在翻页、排序（综合/好评率）、重置时持续生效；若 URL/SEO 丢参则修复
4. **数据**：确认 `is_signed` / `is_trusted` 迁移回填可用；仅在有漏标时做最小 fixup，不改口径

### 验收

- 勾选筛选后每一页结果项均有「信」标
- 取消勾选 / 重置恢复全量
- 切换排序后筛选条件仍生效

### 非目标（72）

- 不改为「仅 is_trusted」严格口径
- PXB 列表若共用同一 badge 判断则一并修正，否则不改 PXB 独立质量筛选项语义

## §75 内训课价格三态（待定 / 免费 / 金额）

### 根因

迁移对非 OPEN 课程强制 `price/original_price = 0`，且 `is_free = 1 if price <= 0`，老站「待定」被标成免费；Hero 见 `isFree===1` 打「免费」标；内训侧栏无「培训参考价」区块。

### 三态约定

| 状态 | 条件 | 详情右侧 | Hero 标签 | 列表价 |
|------|------|----------|-----------|--------|
| 金额 | `price > 0` | 培训参考价：¥xxx | 无免费标 | ¥xxx |
| 免费 | `is_free = 1`（通常 `price = 0`） | 培训参考价：免费 | 「免费」 | 免费 |
| 待定 | `price = 0` 且 `is_free = 0` | 培训参考价：待定 | 无免费标 | 待定 |

不加 `price_status` 列；`price` 保持非空数值约定。

### 迁移 / 回填

1. 修改 `run_legacy_courses_migrate.py`：内训写入真实 legacy 金额（`>0` 保留）；无价/待定 → `price=0, is_free=0`；仅明确免费才 `is_free=1`
2. data-trans 存量 fixup：按老库重算内训 `price` / `is_free`
3. 不改公开课价格迁移与展示逻辑

### C 端 UI

1. **详情侧栏（内训）**：模块顶部增加「培训参考价」区块，样式复用公开课价区；下方 CTA（立即报名等）下移
2. **Hero**：仅 `isFree === 1` 显示免费标
3. **内训列表卡**：按三态渲染价格文案

### 非目标（75）

- 不改公开课、机构页原有价格逻辑
- 不新增价格状态枚举列
