---

## 1. 背景与目标

### 现状问题

Hero 通栏 `w-full`，照片用相对左侧红板的绝对坐标（约 `left: 63px`），右上操作 `absolute right-[24px]` 相对整段白区。下方 Tab / 简介区仍在 `max-w-[1400px] mx-auto px-6` 内。

宽屏时会出现：

- 照片与文案相对下方白卡片**偏左**
- 右上按钮相对「给专家留言」**偏右**
- 左侧红区视觉上不够宽

### 目标

采用 **方案 A + 红区形态 B + 实现路线方案 1**：

1. 红区仍贴浏览器最左通栏，并**加宽**（照片仍叠在红底上）。  
2. 照片左缘**卡住**下方内容白卡片左缘。  
3. 右上操作组右缘**卡住**「给专家留言」右缘。  
4. 交互与图1结构（高约 322、横排、不折行）保持不变。

---

## 2. 用户决策

| 项 | 选择 |
|----|------|
| 整体策略 | **A**：红通栏贴左加宽；照片/文字/按钮收入与下方同宽的内栏 |
| 红区右边界 | **B**：停在照片右侧一点，照片仍叠在红上（类 Figma，内栏右移后红更宽） |
| 实现路线 | **方案 1**：通栏红底 + `max-w-[1400px] mx-auto px-6` 内容层 |

---

## 3. 布局设计

### 3.1 双层结构

| 层 | 职责 |
|----|------|
| **背景层** | `w-full`、高约 322px。红从视口 `x=0` 铺到「内栏左缘 + 照片宽度 + 右侧余量」；其余为白。装饰图/渐变铺在红区内。 |
| **内容层** | 与 `TrainerDetailPageView` 正文一致：`max-w-[1400px] mx-auto px-6`。内放：左照片 + 中信息 + 右操作/留言。 |

正文参照（勿改文件，仅对齐约定）：

```tsx
// TrainerDetailPageView 下方容器
<div className="max-w-[1400px] mx-auto px-6 pb-6 space-y-6">
```

### 3.2 左锚点（照片）

- 照片左缘 = 内容层内容盒左缘（即 `px-6` 之后的起点，与下方主栏白卡片左缘同一竖线）。  
- 不再用「相对视口左侧固定 63px」作为唯一水平基准。  
- 「信」章仍相对照片右下角叠放。

### 3.3 右锚点（操作与留言）

- 右上：收藏 / 评价 / 联系 / 下载简历。  
- 右下：「给专家留言」。  
- 两者处于同一右列，`items-end`（或等价），**右边线对齐**。  
- 去掉相对整段通栏白区的 `absolute right-[24px]`「贴视口右」行为。

### 3.4 红区加宽（形态 B）

- 红左缘：视口最左（通栏）。  
- 红右缘：覆盖到照片右缘之外一小段（实现时可取「内容层左缘 + 照片外框宽 + 常数余量」，常数对齐对齐现稿观感，约数十像素级）。  
- 宽屏时左「缝」变大 → 红面积增加；缩到 `min-w-[1400px]` 时内栏贴左，红宽接近「余量 + 照片区」，行为可接受。

### 3.5 涉及文件

| 文件 | 改动 |
|------|------|
| `frontend/src/features/trainer/components/detail/TrainerHero.tsx` | 主改：背景层 / 内容层 / 右列对齐 |
| `TrainerDetailPageView.tsx` | **不改**（对齐约定共用同类 class） |
| 公共 layout | **不改** |

## 4. 交互与数据

- 无新接口、无新字段。  
- 收藏 / 评价 Link / 留言 / 联系与下载简历（仅 UI）行为与现网 redesign 一致。

---

## 5. 验收标准

1. 宽屏画竖线：照片左缘与下方「专家简介」类白卡片左缘重合。  
2. 右上按钮组右缘与「给专家留言」右缘重合。  
3. 红贴浏览器最左，且比 redesign 首版更宽；照片叠在红上。  
4. 窗口窄于公共 `min-width`：横向滚动；Hero 仍横排不堆叠。  
5. 无回归：加入对比仍不出现；无抠图分支。

- 无需新单测（纯布局）；既有 `getTrainerDetailTabHref` 评价路径测试保持绿。
