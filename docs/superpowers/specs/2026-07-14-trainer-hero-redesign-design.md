# 专家内页 TrainerHero 改版设计

**日期**：2026-07-14  
**分支**：`0713-lzh`  
**范围**：专家详情 Hero 卡片（图1 / 不抠图）+ 公共站点「固定桌面构图 + 横向滚动」规则接线  
**不在范围**：抠图版（图2）；评价 / 联系 / 下载简历的真实业务；全站逐页清除所有响应式断点；列表页 / 用户中心 / Auth / PXB embed 的视觉改版

**Figma 参考**：[淘课网UI · node 17:80](https://www.figma.com/design/oH4ffDnHm2XLhgwLzXKyOw/%E6%B7%98%E8%AF%BE%E7%BD%91UI?node-id=17-80)  
**对齐节点（图1）**：`17:4` Hero / 专家卡片（矩形证件照，非抠图）

---

## 1. 背景与目标

### 现状

- `TrainerHero`：`flex-col xl:flex-row` 自适应；头像下方「给专家留言 / 收藏讲师 / 加入对比」。
- 页面包在 `TrainerDetailPageView` 的 `max-w-[1400px] mx-auto` 内，宽屏约 1080px 内容宽。
- 用户希望专家卡左右拉满浏览器宽度，且**整站公共前台不做小屏改排**：窄窗时内容贴左、用横向滚动查看，而不是折行重排。

### 本期目标

1. 按 Figma **图1** 重做专家内页 Hero（左红右白、固定高度横排）。
2. 公共 layout 接线「`min-width` + `overflow-x: auto`」，为后续全站去自适应打底；本期**不**清光其它页面的 `md:` / `lg:`。
3. 操作区对齐 Figma；去掉「加入对比」。

## 4. 布局与结构

### 4.1 涉及文件

| 文件 | 改动 |
|------|------|
| `frontend/src/features/trainer/components/detail/TrainerHero.tsx` | 主改：版式、操作区、装饰、水印 |
| `frontend/src/features/trainer/components/detail/TrainerDetailPageView.tsx` | Hero 通栏 100%；正文区可暂留现有 `max-w-[1400px]` 容器，避免一次改爆 |
| `frontend/src/app/[locale]/(public)/layout.tsx`（及必要的外层壳） | 接线 `min-width` + `overflow-x: auto` |
| `frontend/public/statics/images/...` | 评价 / 联系 icon；TAOKE 水印资源 |

### 4.2 TrainerHero 构图（始终横排）

| 区域 | 规则 |
|------|------|
| 整卡 | `width: 100%`；`height: 322px` 固定；左红右白；无 `flex-col` / 断点换行 |
| 左侧 | 宽固定（Figma ≈ 339px）；红底渐变 + 平行四边形装饰；白边矩形头像；`isTrusted === 1` 时右下叠「信」章 |
| 右侧 | 余下宽度全部给信息区；随浏览器变宽只加宽右侧 |
| 窄屏 | 不折行；依赖页面级横向滚动看全 |

### 4.3 通栏与正文

- Hero **移出**（或打断）中间栏 `max-w-[1400px]`，保证左右到浏览器内容区边缘（相对 `main` 为 100% 宽）。
- 面包屑与下方 Tab / 侧栏：**本期可不强制通栏**，可仍放在现有限宽容器内。

### 4.4 全局壳（本期只接线）

- 公共前台 layout：设定桌面 `min-width`（实现时按现网主栏习惯取值，目标约 **1400px**）+ `overflow-x: auto`。
- 窗口窄于 `min-width`：出现横向滚动；布局贴左；**不做**小屏改排。
- PXB embed 布局保持独立，不套用本规则（现有分支逻辑保留）。
- 用户中心 / Auth：**不在本期改动范围**（决策「全站公共前台」；中心区另议）。

## 5. 信息区与交互

### 5.1 右侧信息顺序（上 → 下）

1. 姓名（大号加粗）+ 头衔（浅红渐变条底，按 Figma）
2. 专家驻地：图钉 + 省市文案
3. 擅长领域 / 擅长行业：红描边胶囊（行业行标签文案为「擅长行业」，不跟稿笔误「擅长领域」）
4. 底行：左浅灰统计盒 + 右主按钮「给专家留言」

### 5.2 统计盒

- 暂无评分：无分时显示「暂无评分」+「—」；有分时沿用现有星级/`score` 展示逻辑，视觉对齐新盒样式。
- 累计咨询：`consultationCount`
- 累计曝光：现有 `viewCount` → `xk+` 格式；数字强调色按稿（红）

### 5.3 右上操作

| 按钮 | 行为 |
|------|------|
| 收藏 | 现有 `addFavorite` / `removeFavorite`；需登录门禁；文案「收藏」/「已收藏」 |
| 评价 | 导航至本页学员评价 Tab：`getTrainerDetailTabHref(trainerId, 'comments')`（或等价路由工具） |
| 联系 | 仅样式；可 `type="button"`，无跳转 / 无 toast（或实现时统一为无操作） |
| 下载简历 | 仅样式；无下载 |

### 5.4 主 CTA

- 「给专家留言」：现有 `TrainerMessageDialog` + `requireAuth`；位置在右侧底栏靠右（不再放在头像下方）。

### 5.5 移除

- 「加入对比」按钮及头像下方按钮组整体移除。

### 5.6 数据

- 仍使用现有 `TrainerDetail`；**无新后端字段 / 接口**。
- 头像：`trainer.avatar` 矩形展示（不抠图）。

## 6. 视觉还原

### 6.1 左侧红底与平行四边形

- 以 Figma `17:4` 为准。
- 底色渐变参考（实现时以 Dev Mode / MCP 导出值为准）：约  
  `rgb(140, 20, 31) → rgb(191, 31, 38) → rgb(229, 33, 23)`（角度约 162°）。
- 平行四边形：色相、透明度、倾斜角度与稿一致；**优先 CSS**（多层 `linear-gradient` / `skew` / 绝对定位层）；肉眼对不齐时从 Figma 导出 SVG/切图进 `public/statics`。
- 用户聊天中提供的红底 PNG **仅作参考**，不作为唯一真源硬铺（避免与矢量层不一致）。

### 6.2 水印

- 资源：用户提供的 TAOKE Logo（含图形）。
- 叠在右侧白底信息区后层；低透明度（对齐用户素材与截图观感；可与稿中约 `rgba(172,172,172,0.05)` 文字水印同级「很淡」）。
- `pointer-events: none`；不挡点击。

### 6.3 Icon

- 评价、联系：使用用户提供的 PNG/SVG，放入 `frontend/public/statics/images/icons/`（命名实现时约定，如 `trainer-hero-review.png`、`trainer-hero-contact.png`）。
- 收藏、留言：复用现有 Lucide / 项目 icon。
- 「信」章：复用 `/statics/images/icons/trusted-xin.png`。

### 6.4 其它视觉细节

- 标签：红边红字圆角胶囊；领域 / 行业两行。
- 右上三钮：浅底描边小按钮；「下载简历」单独描边按钮在其下。
- 主按钮：实心品牌红、圆角约 4px。
- 统计盒：浅灰圆角底（约 `rgba(245,246,248,0.92)`）。

## 7. 错误处理与边界

| 场景 | 行为 |
|------|------|
| 头像缺失 | 沿用 `SafeImage` 现有占位 |
| 无头衔 / 无驻地 / 无标签 | 对应行隐藏，不留大块空洞（高度仍尽量维持 322px，允许右侧内部间距微调） |
| 收藏失败 | 沿用 apiClient / toast 现有错误提示 |
| 未登录点收藏 / 留言 | `requireAuth` 现有门禁 |
| 评价 Tab 路由 | 使用现有 trainer 路由工具，避免硬编码错误 path |

---

## 8. 验收标准

1. 桌面宽屏：Hero 高约 322px，左固定、右拉宽，视觉接近 Figma 图1。  
2. 缩窄窗口：整页出现横向滚动，Hero **不**变成上下堆叠。  
3. 收藏 / 留言可用；评价进入「学员评价」；联系、下载简历可点但无业务副作用。  
4. 「加入对比」不再出现。  
5. 无抠图分支 / 无透明底特殊布局。  
6. 水印与红底装饰肉眼对齐 Figma（色、透明、斜切）。  
7. 公共 layout 具备 `min-width` + 横向滚动；PXB embed 不受影响。
