# 淘课网 v2 — 角色体系

## 1. 角色分类总览

平台角色分为三大阵营：**需求方**（花钱买服务）、**供给方**（提供培训资源）、**运营方**（管理平台）。

| 阵营 | 角色编码 | 角色名称 | 注册方式 |
|------|---------|---------|---------|
| 需求方 | `ENTERPRISE_BUYER` | B端企业甲方 | 自助注册，即时生效 |
| 需求方 | `INDIVIDUAL_BUYER` | C端个人甲方 | 自助注册/第三方登录，即时生效 |
| 供给方 | `TRAINER` | 讲师 | 自助注册 → 入驻申请 → 后台审核 |
| 供给方 | `AGENT` | 讲师经纪人 | 自助注册 → 入驻申请 → 后台审核 |
| 供给方 | `ORGANIZATION` | 机构 | 自助注册 → 入驻申请（含企业实名）→ 后台审核 |
| 运营方 | `FRONTEND_CS` | 前台客服 | 超级管理员后台创建 |
| 运营方 | `BACKEND_CS` | 后台客服 | 超级管理员后台创建 |
| 运营方 | `SUPER_ADMIN` | 超级管理员 | 系统初始化 / 其他超管创建 |

## 2. 角色详解

### 2.1 B端企业甲方（ENTERPRISE_BUYER）

- **定位**：企业培训需求方，平台核心付费用户
- **扩展信息**：`enterprises` 表（企业名称、行业、规模、联系人、培训需求标签）
- **业务范围**：
  - 检索讲师/课程/机构
  - AI 智能匹配讲师
  - 发布培训需求（不对外公开，同步至客服工作台）
  - 购买在线课/报名公开课
  - 账户充值（分档折扣：1000/5000/10000 元）
  - 评价讲师/机构/课程
  - 收藏课程
- **特殊规则**：
  - 同一企业可多人注册独立账号，不设主从/子账号体系
  - 用户标签关联充值折扣和版权课访问权限

### 2.2 C端个人甲方（INDIVIDUAL_BUYER）

- **定位**：个人学习需求方，次要付费用户
- **扩展信息**：`individual_buyer_profiles` 表（职业、学习兴趣标签）
- **业务范围**：
  - 检索课程
  - 购买在线课、报名公开课
  - 在线学习（视频进度跟踪、笔记、章节试听）
  - 评价课程
  - 收藏课程
- **特殊规则**：
  - 支持微信/支付宝第三方快捷登录
  - 观看付费在线课时单设备播放限制（新设备踢旧设备播放会话）

### 2.3 讲师（TRAINER）

- **定位**：平台核心内容生产者与培训资源供给方
- **扩展信息**：`trainers` 表（头衔、擅长领域、报价范围、认证等级、平均评分）
- **业务范围**：
  - 管理个人主页（简介美化：字体颜色/大小/格式、图片编辑）
  - 发布课程（4 种类型：在线课、线下公开课、内训课、版权课）
  - 管理授课案例（企业名称 + 培训效果，经审核后展示）
  - 上传精彩片段（授课视频片段）
  - 查看收益与数据统计
  - 提现
- **关联关系**：
  - 可被多个经纪人管理（需讲师确认绑定）
  - 可挂靠多个机构
  - 发布的课程被甲方购买/评价
- **特殊规则**：
  - 入驻需后台审核，审核结果通过短信+站内消息通知
  - 资质可升级，升级后增加平台曝光权重，优先推荐
  - 授课案例需后台客服审核后展示

### 2.4 讲师经纪人（AGENT）

- **定位**：培训资源中介，连接讲师与培训需求方
- **扩展信息**：`agents` 表（公司名称、核心运营领域、审核状态）
- **业务范围**：
  - 维护旗下讲师资源库（添加/绑定讲师）
  - 上传讲师资料（支持 DOCX/PDF/PPT/JPG/PNG 多格式）
  - 按领域分类管理讲师、为讲师打标签
  - 接收平台推送的培训需求
  - 筛选匹配旗下讲师并向平台推荐
  - 查看旗下讲师运营数据
- **关联关系**：
  - 一个经纪人管理多个讲师（多对多），绑定需讲师确认
- **特殊规则**：
  - 仅在讲师授权下可编辑讲师部分信息（如课程报价）
  - 经纪人不直接发布课程
  - 入驻申请草稿保留 30 天

### 2.5 机构（ORGANIZATION）

- **定位**：专业培训服务运营方，具备课程研发和讲师团队管理能力
- **扩展信息**：`organizations` 表（机构名称、类型、营业执照、审核状态）
- **业务范围**：
  - 管理机构主页
  - 管理旗下师资团队（讲师挂靠）
  - 发布课程（尤其公开课批量排课：多城市/多时间）
  - 管理公开课状态流转（招生中 → 确认开课 → 已取消）
  - 查看收益与评价
- **关联关系**：
  - 一个机构管理多个讲师（挂靠关系）
  - 机构可独立发布课程
- **特殊规则**：
  - 区分高校与非高校（`org_type` 字段）
  - 高校可公开联系方式，非高校不可公开（甲方不可直接对接非高校机构）
  - 入驻需企业实名认证（营业执照校验）
  - 资质升级影响曝光权重与搜索排序

### 2.6 前台客服（FRONTEND_CS）

- **定位**：一线服务支撑，面向用户实时在线咨询
- **业务范围**：
  - 在线聊天接待用户（文字/图片/链接/快捷回复）
  - 查看 AI 机器人对话记录并接管人工服务
  - 知识库检索辅助回答常见问题
  - 将复杂问题转接后台客服（同步聊天记录）
  - 标注/归档咨询会话
- **特殊规则**：
  - 有独立客服工作台
  - 可查看个人服务数据（今日/本周/本月接待量、问题解决率、用户满意度）
  - 培训需求同步外部系统失败时，工作台显示告警通知

### 2.7 后台客服（BACKEND_CS）

- **定位**：后端运营支撑，平台内容和质量的守门人
- **业务范围**：
  - **全维度审核**：讲师/机构/经纪人入驻审核、课程审核、版权课审核、评价审核
  - **资料维护**：讲师/机构信息编辑、比价管理
  - **用户管理**：冻结/解冻账号、批量编辑用户标签
  - **数据操作**：批量导入/导出用户、讲师、课程数据
  - **问题处理**：处理前台客服转接的复杂问题与用户申诉
  - **内容运营**：CMS 内容管理（轮播图、推荐位、热搜词等）
  - **数据统计**：平台运营数据统一汇总，支持多维度导出
- **特殊规则**：
  - 通过 RBAC 进行细粒度权限控制（如 A 只审核入驻，B 只审核课程）
  - 无权限的模块在导航菜单中隐藏，直接访问 API 返回 403
  - 关键操作（删除数据、冻结账号、退款审批等）需二次确认

### 2.8 超级管理员（SUPER_ADMIN）

- **定位**：系统最高权限管理者
- **业务范围**：
  - 后台客服的全部能力
  - 创建/管理客服与管理员账号
  - RBAC 角色与权限配置（创建角色、分配权限节点、为用户分配角色）
  - 系统全局配置（提现规则、审核时效、短信模板、草稿保留时长等）
  - 第三方接口配置（支付、短信、视频存储、外部系统同步）
  - 系统备份与恢复
  - 系统操作日志查看
- **特殊规则**：
  - 绕过权限校验，拥有所有功能的访问权
  - `SUPER_ADMIN` 为系统内置角色，不可删除/停用
  - 系统必须至少保留一个超级管理员账号

## 3. 角色间关系

### 3.1 供给侧关系

| 关系 | 类型 | 说明 |
|------|------|------|
| 经纪人 → 讲师 | 多对多 | 一个经纪人管理多个讲师，一个讲师也可被多个经纪人管理；绑定需讲师确认 |
| 机构 → 讲师 | 多对多 | 一个机构有多个挂靠讲师，一个讲师可挂靠多个机构 |
| 讲师 → 课程 | 一对多 | 讲师可发布多门课程，内训课与讲师强绑定 |
| 机构 → 课程 | 一对多 | 机构可独立发布课程（尤其公开课） |

### 3.2 交易关系

| 关系 | 说明 |
|------|------|
| 甲方 → 课程 | 企业甲方和个人甲方都可购买在线课/报名公开课 |
| 甲方 → 培训需求 | 企业甲方发布培训需求，AI 匹配推荐讲师 |
| 甲方 → 评价 | 甲方对讲师/机构/课程进行评价（星级+文字+图片） |
| 讲师/机构 → 提现 | 供给方通过平台结算收益 |

### 3.3 运营关系

| 关系 | 说明 |
|------|------|
| 前台客服 ↔ 用户 | 在线实时咨询接待 |
| 前台客服 → 后台客服 | 复杂问题转接，同步聊天记录 |
| 后台客服 → 供给方 | 审核讲师/经纪人/机构入驻申请、审核课程内容 |
| 超级管理员 → 所有角色 | 创建客服账号、配置权限、系统级管理 |

## 4. 多角色支持

一个用户可以同时拥有多个角色，通过 `user_roles` 表的 `(user_id, role)` 联合唯一索引支持。

### 4.1 常见多角色组合

| 组合 | 场景 |
|------|------|
| INDIVIDUAL_BUYER + TRAINER | 个人用户完成讲师入驻后，既能买课也能卖课 |
| ENTERPRISE_BUYER + TRAINER | 企业用户同时也是讲师 |
| TRAINER + AGENT | 一个人既是讲师又代理其他讲师 |
| BACKEND_CS + FRONTEND_CS | 一个客服同时负责前台接待和后台审核 |

### 4.2 角色状态管理

每个角色独立管理状态，互不影响：

| 状态 | 编码 | 说明 |
|------|------|------|
| 生效 | 1 | 角色正常使用 |
| 待审核 | 2 | 入驻申请已提交，等待后台审核 |
| 审核驳回 | 3 | 审核未通过，可重新提交 |
| 已禁用 | 4 | 管理员手动禁用 |

- 企业甲方和个人甲方注册即生效，无需审核
- 讲师、经纪人、机构需审核后生效
- 客服和管理员由超级管理员创建即生效

## 5. 数据表关联

| 角色 | 用户基础表 | 角色扩展表 | 说明 |
|------|-----------|-----------|------|
| 所有角色 | `users` | `user_roles` | 用户身份 + 角色列表 |
| 企业甲方 | `users` | `enterprises` | 一对一，企业信息 |
| 个人甲方 | `users` | `individual_buyer_profiles` | 一对一，个人档案 |
| 讲师 | `users` | `trainers` | 一对一，讲师档案 |
| 经纪人 | `users` | `agents` | 一对一，经纪人档案 |
| 机构 | `users` | `organizations` | 一对一，机构档案 |
| 经纪人-讲师 | — | `agent_trainers` | 多对多关联 |
| 机构-讲师 | — | `organization_trainers` | 多对多关联 |
| RBAC 授权 | `users` | `user_role_assignments` + `roles` + `role_permissions` + `permissions` | 后台细粒度权限 |

## 6. 待讨论事项

- **多组织支持**：当前设计中经纪人和机构都是单账号，未支持"组织内多员工多权限"。如果后续需要（如一个机构下有多个员工各自登录并拥有不同操作权限），需要增加组织-成员-组织内角色这一层。
