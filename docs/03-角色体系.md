# 淘课网重构v2 — 角色体系

## 1. 角色分类总览

平台角色分为三大阵营：**需求方**（花钱买服务）、**供给方**（提供培训资源）、**运营方**（管理平台）。


| 阵营      | 角色编码                   | 角色名称    | 注册方式                      |
| ------- | ---------------------- | ------- | ------------------------- |
| 需求方（甲方） | `ENTERPRISE_BUYER`     | 企业培训采购方 | 手机号注册，其他注册方式 P2 迭代        |
| 需求方（甲方） | `BUYER`                | 个人学员    | 手机号注册，其他注册方式 P2 迭代        |
| 供给方（丙方） | `TRAINER`              | 专家      | 手机号注册 → 入驻申请 → 后台审核       |
| 供给方（丙方） | `AGENT`                | 专家经纪人   | 手机号注册 → 入驻申请 → 后台审核       |
| 供给方（丙方） | `ASSISTANT`            | 专家助理    | 手机号注册 → 入驻申请 → 后台审核       |
| 供给方（丙方） | `ENTERPRISE_AGENT`     | 专家经纪公司  | 手机号注册 → 入驻申请 → 后台审核       |
| 供给方（乙方） | `INSTITUTION`          | 机构      | 手机号注册 → 入驻申请（含企业实名）→ 后台审核 |
| 供给方（乙方） | `INSTITUTION_EMPLOYEE` | 机构员工    | 手机号注册 → 入驻申请（含企业实名）→ 后台审核 |
| 运营方     | `PLATFORM_AUDITOR`     | 平台审核员   | 超级管理员后台创建                 |
| 运营方     | `PLATFORM_CS`          | 平台客服    | 超级管理员后台创建                 |
| 运营方     | `SUPER_ADMIN`          | 超级管理员   | 系统初始化 / 其他超管创建            |


共 8 个平台业务角色 + 3 个平台运营角色。

## 2. 角色详解

### 2.1 企业培训采购方（ENTERPRISE_BUYER）

- **定位**：企业培训需求方，平台核心付费用户
- **业务范围**：
  - 检索专家/课程/机构
  - AI 智能匹配专家
  - 发布培训需求（不对外公开，同步至客服工作台）
  - 购买在线课/报名公开课
  - 评价专家/机构/课程/案例/视频
  - 收藏课程
- **特殊规则**：
  - 同一企业可多人注册独立账号，不设主从/子账号体系
  - 用户标签关联版权课访问权限

### 2.2 个人学员（BUYER）

- **定位**：个人学习需求方，次要付费用户
- **业务范围**：
  - 检索课程
  - 购买在线课、报名公开课
  - 在线学习（视频进度跟踪、笔记、章节试听）
  - 评价课程/案例/视频
  - 收藏课程
- **特殊规则**：
  - 观看付费在线课时单设备播放限制（新设备踢旧设备播放会话）

### 2.3 专家（TRAINER）

- **定位**：平台核心内容生产者与培训资源供给方
- **业务范围**：
  - 管理个人主页（简介美化：字体颜色/大小/格式、图片编辑）
  - 发布课程（4 种类型：在线课、线下公开课、内训课、版权课）
  - 管理授课案例（企业名称 + 培训效果，经审核后展示）
  - 上传精彩片段（授课视频片段）
  - 查看收益与数据统计
- **关联关系**：
  - 可被多个经纪人管理（需专家确认绑定）
  - 一个专家只能关联一个助理（需专家确认绑定）
  - 可挂靠多个机构（需专家确认绑定）
  - 发布的课程被甲方购买/评价
- **特殊规则**：
  - 入驻需后台审核，审核结果通过短信+站内消息通知
  - 资质可升级，升级后增加平台曝光权重，优先推荐

### 2.4 专家经纪人（AGENT）

- **定位**：培训资源中介，连接专家与机构，不直接接触甲方需求方
- **业务范围**：
  - 维护旗下专家资源库（添加/绑定/解绑专家）
  - 上传专家资料（支持 DOCX/PDF/PPT/JPG/PNG 多格式）
  - 按领域分类管理专家、为专家打标签
  - 筛选匹配旗下专家并向平台推荐
  - 查看旗下专家运营数据
- **特殊规则**：
  - 可编辑旗下专家信息、专家课程、案例、视频等
  - 可以关联经纪公司

### 2.5 专家助理（ASSISTANT）

- **定位**：专家的个人行政与教务协助人员，辅助专家处理日常运营事务
- **业务范围**：
  - 协助资料维护：编辑并更新所绑定专家的个人主页、课程信息、授课案例及视频片段等
  - 教务管理：管理专家的授课排期，协助跟进课程的发布与下架
  - 数据查看：查看所绑定专家的收益明细及运营统计数据
- **特殊规则**：
  - 强绑定关系：一个专家只能关联一个助理
  - 确认机制：助理与专家的绑定关系，均需专家本人确认后方可生效

### 2.6 专家经纪公司（ENTERPRISE_AGENT）

- **定位**：具备多经纪人管理能力，并且可以管理旗下讲师
- **业务范围**：
  - 资源池管理：维护公司旗下的专家资源库，进行专家的添加、绑定与解绑操作
  - 团队权限分配：管理关联的个人经纪人（AGENT），与「机构-机构员工」类似的隶属关系
  - 批量内容运营：代表旗下专家发布课程、上传案例资料
  - 财务汇总：统一查看旗下所有专家及经纪人的运营数据
- **特殊规则**：
  - 企业实名制：入驻时需进行企业实名认证，提交营业执照等资质证明
  - 第一个认证该公司的经纪人默认为经纪公司负责人
  - **隶属关系**：经纪公司与经纪人之间为「公司 ↔ 成员」隶属关系，类似 INSTITUTION ↔ INSTITUTION_EMPLOYEE。
    - 经纪公司可邀请/批准经纪人加入旗下，使用绑定表 `user_enterprise_agent_members`（agentUserId ↔ enterpriseAgentUserId）。
    - 旗下经纪人对经纪公司直管的专家自动具备代管权限（无需重复绑定到具体专家）。
  - 多经纪人关联：一个专家经纪公司可以关联多个专家经纪人
  - 审核机制：需通过平台后台的人工严格审核

### 2.7 机构（INSTITUTION）

- **定位**：专业培训服务运营方，具备课程研发和专家团队管理能力
- **业务范围**：
  - 管理机构主页
  - 管理旗下师资团队（专家挂靠）
  - 发布课程（尤其公开课批量排课：多城市/多时间）
  - 管理公开课状态流转（招生中 → 确认开课 → 已取消）
  - 机构也需要有发布需求的功能
  - 查看收益与评价
- **特殊规则**：
  - 区分高校与非高校（org_type 字段）
  - 高校可公开联系方式，非高校不可公开
  - 入驻需企业实名认证（营业执照校验）
  - 可以管理机构员工

### 2.8 机构员工（INSTITUTION_EMPLOYEE）

- **定位**：机构内部的运营人员，在机构授权范围内执行日常业务
- **业务范围**：
  - 管理旗下师资团队（专家挂靠）
  - 发布课程（尤其公开课批量排课：多城市/多时间）
  - 管理公开课状态流转（招生中 → 确认开课 → 已取消）
  - 机构员工也可发布需求
  - 查看评价
- **特殊规则**：
  - 需机构验证绑定关系

### 2.9 平台审核员（PLATFORM_AUDITOR）

- **定位**：后台管理相关业务
- **业务范围**：
  - 全维度审核：专家/机构/经纪人入驻审核、课程审核、版权课审核、评价审核
  - 资料维护：专家/机构信息编辑、比价管理
  - 用户管理：冻结/解冻账号、批量编辑用户标签
  - 数据操作：批量导入/导出用户、专家、课程数据
  - 问题处理：处理前台客服转接的复杂问题与用户申诉
  - 内容运营：CMS 内容管理（轮播图、推荐位、热搜词等）
  - 数据统计：平台运营数据统一汇总，支持多维度导出
- **特殊规则**：
  - 通过 RBAC 进行细粒度权限控制（如 A 只审核入驻，B 只审核课程）
  - 关键操作需二次确认

### 2.10 平台客服（PLATFORM_CS）

- **定位**：服务支撑
- **业务范围**：
  - 平台客服

### 2.11 超级管理员（SUPER_ADMIN）

- **定位**：系统最高权限管理者
- **业务范围**：
  - （拥有平台审核员和平台客服的全部能力）
- **特殊规则**：
  - 绕过权限校验，拥有所有功能的访问权
  - 不可删除/停用
  - 系统必须至少保留一个超级管理员账号

## 3. 角色间关系

### 3.1 供给侧关系


| 关系         | 类型  | 说明                                  |
| ---------- | --- | ----------------------------------- |
| 经纪人 → 专家   | 多对多 | 多个经纪人可管理同一个专家；一个经纪人也可管理多个专家。绑定需专家确认 |
| 经纪公司 → 专家  | 多对多 | 经纪公司可直管多个专家（绑定需专家确认）；经纪公司直管的专家，旗下经纪人均可代管 |
| 机构 → 专家    | 多对多 | 一个机构可挂靠多个专家，一个专家可挂靠多个机构             |
| 专家 → 课程    | 一对多 | 专家可发布多门课程，内训课与专家强绑定                 |
| 机构 → 课程    | 一对多 | 机构可独立发布课程（尤其公开课）                    |
| 专家 → 助理    | 一对一 | 一个专家只能关联一个助理，绑定需专家确认                |
| 经纪公司 → 经纪人 | 一对多 | **隶属关系**，类似机构 ↔ 机构员工，由经纪公司发起邀请，经纪人确认 |
| 机构 → 机构员工  | 一对多 | **隶属关系**，由机构发起邀请，员工确认               |

#### 3.1.1 绑定关系数据模型

平台使用以下绑定表落地角色之间的关系（绑定状态：`PENDING` / `ACTIVE` / `REJECTED` / `UNBOUND`）：

| 绑定表                                    | 含义                              | 发起方                  | 确认方             |
| ------------------------------------- | ------------------------------- | -------------------- | --------------- |
| `user_agent_trainer_bindings`         | 经纪人 ↔ 专家                        | 经纪人 / 专家             | 专家              |
| `user_trainer_assistant_bindings`     | 专家 ↔ 助理（专家维度唯一）                 | 专家 / 助理              | 专家              |
| `user_institution_trainer_bindings`   | 机构 ↔ 专家                         | 机构 / 专家              | 专家              |
| `user_institution_employee_bindings`  | 机构 ↔ 机构员工（隶属关系）                 | 机构                   | 员工              |
| `user_enterprise_agent_members`       | 经纪公司 ↔ 经纪人（隶属关系，类同机构↔员工）        | 经纪公司                 | 经纪人             |
| `user_enterprise_agent_trainer_bindings` | 经纪公司 ↔ 专家（直管）                 | 经纪公司 / 专家            | 专家              |

#### 3.1.2 资源代管权限派生

当一名运营角色（机构 / 经纪人 / 经纪公司 / 助理 / 机构员工）以 `ACTIVE` 状态绑定到某个专家后，该角色即获得对该专家以下资源的「代管」权限：

- 课程（含在线课、公开课、内训课、版权课）
- 授课案例
- 精彩瞬间
- 录播课/视频
- 著作

派生规则：

- **经纪公司直管的专家**：旗下所有 `ACTIVE` 经纪人（来自 `user_enterprise_agent_members`）自动获得对该专家的代管权限。
- **机构直管的专家**：机构旗下所有 `ACTIVE` 机构员工（来自 `user_institution_employee_bindings`）自动获得对该专家的只读/代管权限（依业务设置）。
- 这一权限派生由 `BindingAuthorizationService` 在后端集中计算，前端通过 `TrainerSwitcher` 选择当前要管理的专家上下文，并以 `trainerUserId` 参数传入资源 API。


### 3.2 交易关系


| 关系        | 说明                         |
| --------- | -------------------------- |
| 甲方 → 课程   | 企业甲方和个人学员都可购买在线课/报名公开课     |
| 甲方 → 培训需求 | 企业甲方发布培训需求                 |
| 甲方 → 评价   | 甲方可对专家/机构/课程进行评价（星级+文字+图片） |


### 3.3 运营关系


| 关系    | 说明                        |
| ----- | ------------------------- |
| 平台审核员 | 审核专家/经纪人/机构入驻申请、审核课程内容等业务 |
| 平台客服  | 平台的客服类角色                  |
| 超级管理员 | 创建客服账号、配置权限、系统级管理等        |


## 4. 多角色支持

一个用户可以同时拥有多个角色。

共 8 个平台业务角色和 3 个平台运营角色，任何角色的前提，是一个基础用户。有的角色需要通过审核以后才可获得。一个用户可以是多个角色的组合。

- **BUYER（个人学员）为平台默认角色**：所有用户注册时自动赋予，无需审核。未注册用户通过验证码登录自动开户时也会赋予 BUYER 角色
- 企业培训采购方（ENTERPRISE_BUYER）在注册后通过补充企业信息申请，无需审核
- 专家、专家经纪人、专家助理、专家经纪公司、机构、机构员工需要后台审核后才生效获得角色
- 平台角色（审核员、客服、超管）由后台管理员创建

### 常见多角色组合


| 组合                         | 场景                               |
| -------------------------- | -------------------------------- |
| BUYER + TRAINER            | 个人用户完成专家入驻后，既是个人学员，也是专家，既能买课也能卖课 |
| ENTERPRISE_BUYER + TRAINER | 企业培训采购方的同时，也是专家                  |
| TRAINER + AGENT            | 一个用户既是专家，又是专家经纪人                 |
