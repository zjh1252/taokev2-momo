# 淘课网 v2 重构项目介绍

## 1. 项目定位

**淘课网（taoke）** 是面向 B 端的 **企业培训采购平台**，连接：

- **需求方（甲方）**：企业培训采购方、个人学员；
- **供给方（乙/丙方）**：专家、专家经纪人 / 经纪公司、专家助理、培训机构 / 机构员工；
- **运营方**：平台审核员、客服、超级管理员。

形成 "资源展示 → 需求对接 → 下单交易 → 价值交付 → 评价反馈" 的业务闭环。
v2 版本为完整重构，从零搭建前后端分离体系。

## 2. 仓库结构总览

```
taokev2-mono/
├── backend/            # Java 后端（模块化单体，多 Maven Module）
├── frontend/           # C 端门户 + 用户中心（Next.js）
├── admin-frontend/     # 运营管理后台（Next.js）
├── taoke-uniapp/       # 移动端（uni-app + Vue 3）
└── docs/               # 设计文档、PRD、流程文档
```

一仓多端，前后端独立部署，统一通过 REST API 对接后端。

## 3. 后端 `backend/`

后端采用 **模块化单体（Modular Monolith）** ：所有模块编译进同一个可执行 JAR，部署简单；通过 Maven Module 实现编译期隔离，模块间只能通过 `api` 包暴露的接口或事件总线通信，便于未来按域拆分微服务。

### 3.1 模块清单

| 模块 | 职责定位 | 主要业务承载 |
|---|---|---|
| `taoke-common` | 公共基础设施层 | 错误码 / 统一响应、JWT 鉴权与角色注解、文件上传 + 存储抽象（本地 / 对象存储）、Redis + Redisson、RabbitMQ 事件总线、Elasticsearch 客户端、AI 基础能力（OpenAI 兼容协议）、文档抽取（docx / pdf）、敏感词、内容审查、行政区划、统一分类树 |
| `taoke-user` | 用户域 | 用户 + 多角色身份、登录注册（验证码 / 账号密码双通道）、JWT 鉴权、SMS、专家档案、专家四类认证（实名 / 教育 / 工作 / 职业资格）、专家与经纪人 / 助理 / 机构的代管关系、机构员工管理 |
| `taoke-course` | 业务核心域 | 课程发布 / 审核 / 上下架、内训课与公开课（多场次开课计划）、课程 AI 解析、专家案例、精彩瞬间、留言咨询、视频、订单 / 购物车 / 支付 / 报名、收藏 / 点赞 / 评价、企业培训需求、CMS / Banner |
| `taoke-admin` | 后台编排层 | 不直接访问 Repository，调用 `taoke-user` / `taoke-course` 的 `api` 接口完成：用户、专家认证审核、课程 / 视频 / 案例 / 精彩瞬间 / 留言 / 评价审核，敏感词，分类，CMS |
| `taoke-app` | 启动入口 | Spring Boot 启动类、`application.yml` 配置、Flyway 迁移脚本、全局过滤器、最终打包出可执行 JAR |

### 3.2 关键技术栈

| 层次 | 选型 |
|---|---|
| 语言 / 框架 | Java 21 + Spring Boot 3.5 + Spring MVC |
| ORM | Spring Data JPA |
| 鉴权 | Spring Security + JWT + 自定义 `@RequireRole` 注解 + `BindingAuthority` 代管授权 |
| 数据库 | MySQL 8.4 + Flyway 迁移（已演进至 V63） |
| 缓存 | Redis + Redisson（分布式锁） |
| 事件 | RabbitMQ（订单 / 审核 / 通知等领域事件） |
| 搜索 | Elasticsearch（课程 / 专家 `Document` + `DocumentProvider` 同步） |
| AI | `AiChatService`（OpenAI 兼容协议）+ `DocumentTextExtractor` |
| 文档 | springdoc-openapi（Swagger UI） |
| 存储 | `StorageService` 抽象，可切换本地 / 对象存储 |

### 3.3 关键架构点

- **模块化单体**：模块间只能通过 `api` 接口或事件解耦，禁止跨模块直接访问 Entity / Repository。
- **角色与代管授权**：`@RequireRole` 控制接口角色；`BindingAuthority` 实现"经纪人代专家"、"助理代专家"、"机构员工代机构"三类代管行为。
- **统一响应**：`ApiResponse<T>` + `ErrorCode` 枚举（按模块编号 5 位错误码），便于前端统一处理。
- **事件驱动**：审核结果、订单状态、评价审核、认证审核等关键节点通过事件广播，下游订阅者负责通知 / 索引同步等副作用。
- **搜索同步**：领域更新写库后由 `DocumentProvider` 异步推送至 ES，避免业务路径阻塞。

## 4. 前端 `frontend/` — C 端门户 + 用户中心

面向最终用户（学员、企业、专家、经纪人、机构等）的一站式门户。

### 4.1 业务承载

- **公开门户**：首页、课程检索 / 详情、专家检索 / 详情、机构检索 / 详情、案例展示。
- **下单交易**：购物车、订单、支付、订单中心。
- **学员中心**：我的课程、我的订单、收藏、消息、资料编辑。
- **专家入驻 & 经营**：专家入驻表单、四类认证申请与状态查看、课程发布（含 AI 解析一键回填）、案例 / 精彩瞬间发布、留言处理。
- **多角色用户中心**：根据用户角色（专家 / 经纪人 / 助理 / 机构 / 机构员工 / 企业采购）动态渲染侧边栏与功能。

### 4.2 关键技术栈与架构点

- **Next.js 16**（App Router）+ TypeScript + Tailwind CSS + shadcn-ui。
- **国际化**：`next-intl`，路由按 `[locale]` 隔离。
- **数据层**：TanStack Query；统一封装 `apiGet / apiPost / apiPut / apiDelete` + `authHeaders`。
- **目录约定**：`features/<domain>/{api,components,...}` 按业务域聚合，组件库放 `components/`，公共逻辑放 `lib/`。
- **复杂上传**：图片裁剪（`ImageCropperUploader`）、富文本（`RichTextEditor`）、行政区划级联（`RegionCascader`）等已抽组件。

## 5. 管理后台 `admin-frontend/` — 运营管理后台

面向平台运营、审核员、超级管理员的内部系统。

### 5.1 业务承载

- **审核中心**：专家四类认证审核、课程审核、视频审核、专家案例审核、精彩瞬间审核、专家留言审核、用户评价审核（通过 / 驳回 / 隐藏，含驳回原因）。
- **内容管理**：分类树、敏感词库、CMS / Banner、热门搜索词。
- **用户与权限**：用户列表、角色冻结、超管账户管理。
- **统计与监控**（按需扩展）。

### 5.2 关键架构点

- 与 C 端共用技术栈：Next.js 16 + TypeScript + Tailwind + shadcn-ui，但导航 / 主题 / 表格组件相对独立。
- 通过 `nav-config.ts` + RBAC 的菜单配置驱动侧边栏渲染。
- 表格统一基于 TanStack Table 二次封装（列定义 + 单元操作 + 分页查询参数同步到 URL）。

## 6. 移动端 `taoke-uniapp/` — App / 小程序

基于 **uni-app + Vue 3 + Pinia** 构建，一套代码多端发行（H5 / 微信小程序 / iOS / Android）。

### 6.1 业务承载

- **首页**：Banner、课程 / 专家推荐、入口分发。
- **专家 / 课程**：列表、详情、收藏。
- **用户中心**：登录注册（验证码 + 账密）、资料编辑、修改密码、消息列表、收藏。
- **导航**：底部 tabbar 自定义图标，支持深色 / 浅色态。

### 6.2 关键架构点

- **设计 tokens**：`styles/tokens.scss` + `mixins.scss` 统一颜色、间距、阴影、文字层级。
- **自建组件库** `Tk*`：`TkNavBar / TkSearchBar / TkCourseCard / TkExpertCard / TkAvatar / TkSection / TkActionBar / TkFilterBar / TkLoading / TkEmpty / TkIcon` 等，对齐设计稿。
- **请求与鉴权**：`utils/request.js` 统一封装请求 / Token / 错误码处理；`stores/user.js` 持久化登录态。
- **多渠道打包**：`configs/env.js` 切换环境，`manifest.json` 区分 H5 / 小程序 / App。

## 8. 开发协作要点（精简版）

1. **后端新业务**优先放 `taoke-course` 或 `taoke-user`；若是跨模块基础能力（AI、文档抽取、敏感词等）放 `taoke-common`；管理后台仅做编排，不写业务逻辑。
2. **前端新业务**遵循 `features/<domain>` 聚合：`api/{types,service}` + `components/`，避免散落到顶层。
3. **数据库变更**统一通过 Flyway 迁移脚本（`backend/taoke-app/src/main/resources/db/migration/V*.sql`），禁止手改库表。
4. **错误码** 一律走 `ErrorCode` 枚举，新增按模块编号 5 位规则追加。
5. **接口文档** 通过 `@Operation` / `@Tag` 描述，前端按 Swagger 对接；提交前确保 `tsc --noEmit` 与 `mvn compile` 通过。
6. **代码风格**：保持 Java / TypeScript 现有风格；不要写仅复述代码作用的注释，注释解释"为什么 / 约束"。
