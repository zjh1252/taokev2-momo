# 打包发布指南（taoke-uniapp）

本文是 **HBuilderX 模式** 下的发布 SOP，适用于 H5、微信小程序、Android apk、iOS ipa 四个产物。后续切到 CLI 模式（`@dcloudio/vite-plugin-uni`）后会更新本文。

---

## 0. TL;DR · 一分钟速查

| 我要打 | 步骤 |
|---|---|
| **test apk** | 改 `configs/env.js` 的 `APP_ENV_OVERRIDE = 'test'` → HBuilderX → 发行 → 原生App-云打包 → Android → 公共测试证书 → 下载 apk → **改回 `''`** |
| **prod apk** | 直接 HBuilderX → 发行 → 原生App-云打包 → Android → 自有证书（前提：`production` 段域名已替换为真实域名） |
| **test 小程序** | 改 `APP_ENV_OVERRIDE = 'test'` → HBuilderX → 发行 → 小程序-微信 → `unpackage/dist/build/mp-weixin` → 微信开发者工具上传 → **改回 `''`** |
| **prod 小程序** | 同上不改 OVERRIDE，HBuilderX 发行；公众平台「服务器域名」必须白名单生产 API |
| **H5** | HBuilderX → 发行 → 网站-PC Web 或 H5；产物在 `unpackage/dist/build/h5/` |

## 1. 三档环境矩阵

| 环境 | API_BASE_URL | ASSET_BASE_URL | 触发方式 |
|---|---|---|---|
| **development** | `http://localhost:8080` | `http://localhost:8080` | HBuilderX「运行 → 浏览器/小程序模拟器」自动注 `NODE_ENV=development` |
| **test** | `https://v2.taoke.com/backend-api` | `https://v2.taoke.com` | HBuilderX 没有原生 test 档；`configs/env.js` 顶部 `APP_ENV_OVERRIDE = 'test'` 手动切 |
| **production** | `https://api.taoke.com` *(占位)* | `https://cdn.taoke.com` *(占位)* | HBuilderX「发行」自动注 `NODE_ENV=production` |

> `_NATIVE` 后缀变量（`API_BASE_URL_NATIVE` / `ASSET_BASE_URL_NATIVE`）**仅小程序 / 真机 App 使用**；H5 走不带 `_NATIVE` 的版本。配置位置：[configs/env.js](configs/env.js)。

### 1.1 切环境的唯一开关

[configs/env.js](configs/env.js) 顶部：

```javascript
const APP_ENV_OVERRIDE = '';  // '' | 'development' | 'test' | 'production'
```

| 取值 | 行为 |
|---|---|
| `''` | 自动按 `NODE_ENV` 推断（HBuilderX 运行 = dev / 发行 = prod） |
| `'development'` | 强制 dev（极少用，调试 dev 配置） |
| `'test'` | **强制 test**（打测试包必用） |
| `'production'` | 强制 prod（极少用） |

> ⚠️ **每次打完 test 包后务必把这一行改回 `''`**，否则下次本地 dev 启动也会跑 test 域，dev 调试就乱套了。

## 2. App 图标 / 启动图配置（首次打包必看）

### 2.1 当前状态

打开 [manifest.json](manifest.json) 看 `app-plus.distribute`，如果**没有 `icons` 字段** + 没有 `unpackage/res/icons/` 目录 —— 说明项目还没配置图标，打 apk 会用 dcloud 默认图标（橙底白 H）。

### 2.2 配置图标

1. 准备一张 **1024×1024 PNG** 源图（建议透明底；如果图形是浅色，加深色描边避免 iOS 系统底色冲突）
2. HBuilderX 左侧文件树双击 `manifest.json` → 进入**可视化配置界面**（不是源码视图）
3. 左侧切到 **「App 图标配置」** 标签
4. 点「浏览」上传 1024×1024 源图
5. 点 **「自动生成所有图标」** → HBuilderX 一键生成 Android + iOS 全套尺寸
6. 自动保存到 `unpackage/res/icons/`，`manifest.json` 自动写入 `app-plus.distribute.icons` 字段
7. **将 `unpackage/res/icons/` 整个目录加入 git**（这是个 `.gitignore` 例外，详见 §6）

### 2.3 配置启动图（splash）

同上：可视化界面切「App 启动界面配置」标签，上传 **2208×2208 PNG** 源图自动生成各尺寸。建议使用与图标视觉风格一致的简约画面，避免文字（不同尺寸文字会糊）。

## 3. 打 test apk（最常用）

### 步骤

1. **切环境** —— 打开 [configs/env.js](configs/env.js)，把
   ```javascript
   const APP_ENV_OVERRIDE = '';
   ```
   改为
   ```javascript
   const APP_ENV_OVERRIDE = 'test';
   ```

2. **改版本号** —— 打开 `manifest.json` 可视化界面 → 「基础配置」：
   - `versionName`：建议 `1.0.0-test` 或 `1.0.0-rc1`，方便测试同事一眼区分
   - `versionCode`：每次发包**自增 1**（数字型，不能回退；如 100 → 101 → 102）

3. **确认图标已配置**（见 §2）

4. **HBuilderX 顶部菜单 → 发行 → 原生App-云打包**（注意不是「H5」「小程序」「本地打包」）

5. **打包参数**：
   - **平台**：勾 `Android`（如需 iOS 同步勾，要自有 iOS 证书）
   - **Android 包名**：保持 manifest 里现有值（默认 `uni.UNI...`）；正式渠道分发要换成自有包名（如 `com.taoke.app`）
   - **Android 证书**：
     - **测试派发**：勾「使用公共测试证书」（dcloud 提供，免配置，**不能上架应用市场**，仅供内部 / 测试同事使用）
     - **正式分发 / 上架**：勾「使用自有证书」，提前用 `keytool` 生成 `.keystore` 文件（详见 §5）
   - **打包后自动检测原生工程一致性**：勾上
   - **广告联盟**：不勾
   - **更多选项**：保持默认

6. 点 **打包** → 等 5~10 分钟（取决于 dcloud 排队）

7. 控制台底部会打印：
   ```
   apk保存路径：https://ide.dcloud.net.cn/build/download/xxxxxxxx
   ```
   点击下载 → 保存为 `taoke-test-1.0.0-rc1.apk`

8. **手机安装测试**：
   - 把 apk 通过微信文件传输助手 / qq / 数据线传到手机
   - 手机文件管理器点开 → 允许"未知来源"安装 → 完成
   - 启动 app，登录后查看：接口走 `https://v2.taoke.com/backend-api`，头像走 `https://v2.taoke.com`

9. **⚠️ 复原**：把 `APP_ENV_OVERRIDE` 改回 `''`。**这一步特别容易忘**，建议把 §3 步骤打印贴电脑边。

## 4. 打 prod apk

流程同 §3，但有 4 处区别：

| 项 | test | prod |
|---|---|---|
| `APP_ENV_OVERRIDE` | 改成 `'test'` | **保持 `''`**（HBuilderX 发行会自动 NODE_ENV=production） |
| 证书 | 公共测试证书 | **必须自有证书**（应用市场上架强制要求） |
| 包名 | 测试包名（默认即可） | **正式包名**（如 `com.taoke.app`，市场上架后不可修改） |
| 域名前提 | test 段已对齐 | `production` 段占位域名（`api.taoke.com` / `cdn.taoke.com`）必须替换为真实域名 |

> 上架应用市场前还要补：隐私政策声明、敏感权限说明、应用截图、应用描述等。

## 5. 自有证书生成（一次性）

正式包必须有自有签名证书。证书一旦发布到应用市场，**永久不能更换**（更换会导致已安装用户无法平滑升级）。

```bash
# 假设证书放 ~/keys/ 目录
keytool -genkey -alias taoke -keyalg RSA -keysize 2048 -validity 36500 -keystore ~/keys/taoke.keystore
```

输入项：
- 密码：**自定义并保存到密码管理器，丢了无法恢复**
- 姓名 / 组织 / 城市 / 国家代码：随便填，但建议填真实值
- 别名密码：**与上面密码相同**（dcloud 云打包要求）

证书指纹查看：

```bash
keytool -list -v -keystore ~/keys/taoke.keystore -alias taoke
# 找输出里的：
#   SHA1:   xx:xx:xx:...
#   SHA256: xx:xx:xx:...
```

> SHA1 用来：
> - 微信开放平台「应用签名」（开通微信登录 / 分享）
> - 高德 / 百度地图 SDK 的 KEY 配额绑定
> - 微信支付的应用签名验证

把 `taoke.keystore` 上传到 dcloud 云打包页面 → 输入密码 + 别名 + 别名密码 → 选「使用自有证书」即可。

## 6. .gitignore 例外：`unpackage/res/icons/` 必须进 git

`.gitignore` 默认忽略整个 `unpackage/`（构建产物），但 **`unpackage/res/icons/` 是个例外** —— 这里是 HBuilderX 自动生成的应用图标，是源代码的一部分（不是构建产物），换电脑 / 多人协作时必须共享。

[.gitignore](.gitignore) 已添加例外规则：

```gitignore
unpackage/
!unpackage/res/
!unpackage/res/icons/
!unpackage/res/icons/**
```

如果你看到 `git status` 中 `unpackage/res/icons/` 的图标文件没有出现 / 被忽略，检查 `.gitignore` 里这几行例外是否还在。

## 7. 打微信小程序

### 7.1 test 小程序

1. **改 `APP_ENV_OVERRIDE = 'test'`**（同 §3）
2. **配 `mp-weixin.appid`** —— `manifest.json` 里 `mp-weixin.appid` 填写微信公众平台分配的小程序 AppID
3. **HBuilderX → 发行 → 小程序-微信**
4. 产物在 `unpackage/dist/build/mp-weixin/`
5. 用**微信开发者工具**打开该目录 → 上传体验版 → 微信公众平台「版本管理」转体验版
6. ⚠️ **复原** `APP_ENV_OVERRIDE = ''`

### 7.2 域名白名单（必须）

微信小程序 request / downloadFile / uploadFile 域名都要在公众平台预先白名单：

1. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com)
2. 「开发管理 → 开发设置 → 服务器域名」
3. 添加：
   - request 合法域名：`https://v2.taoke.com`
   - downloadFile 合法域名：`https://v2.taoke.com`
   - uploadFile 合法域名：`https://v2.taoke.com`（如有头像 / 文件上传）
4. prod 上线时同步加 `https://api.taoke.com` 与 `https://cdn.taoke.com`

> 没白名单 → 真机请求会报 `request:fail url not in domain list`。开发者工具勾「不校验合法域名」可临时绕过，但真机不行。

## 8. 打 H5

`H5` 通常是部署到 web 服务器（nginx）/ CDN，不需要 dcloud 云打包：

1. **改 `APP_ENV_OVERRIDE = 'test'`**（如打 test）
2. HBuilderX → 发行 → 网站-PC Web 或手机 H5
3. 产物在 `unpackage/dist/build/h5/`
4. 把整个目录上传到 web 服务器 `/var/www/taoke-h5/` 或 OSS / CDN
5. nginx 配置 SPA 路由 fallback：
   ```nginx
   location / {
     try_files $uri $uri/ /index.html;
   }
   ```
6. 复原 `APP_ENV_OVERRIDE`

## 9. 故障排查

### 9.1 apk 装上后白屏

可能原因：
- `APP_ENV_OVERRIDE` 没改 → baseURL 仍是 `localhost`（手机访问不到开发者电脑）
- 证书错误 / 包名冲突 → 卸载手机上其他同包名应用再装
- 启动页 splash 没配 → 黑屏几秒后白屏
- 后端 https 证书无效 → Android 7+ 拒绝自签名证书

排查：
- 用 USB 连手机 → `adb logcat *:E` 看错误
- 微信开发者工具 / 真机调试 webview 看控制台

### 9.2 真机请求超时

- 浏览器试 `https://v2.taoke.com/backend-api/...` 是否正常
- HTTPS 证书必须有效，自签证书 Android 默认不信任
- 检查后端 CORS 是否允许移动端 origin（apk 内嵌 webview 通常 origin 为 `null` 或 `file://`，需后端 `*` 放行或专门加 null）

### 9.3 图片不显示 / 头像不显示

- 检查 `config.assetBaseURL` 实际拼出的 URL，浏览器直接访问能不能打开
- 后端返回相对路径（`/uploads/x.png`）+ 前端 `toAssetUrl` 是否正确拼成 `https://v2.taoke.com/uploads/x.png`
- nginx 是否把 `/uploads/` 路径暴露在主域 `https://v2.taoke.com/uploads/...` 而不是 `/backend-api/uploads/...`

### 9.4 小程序 request:fail url not in domain list

域名没在公众平台「服务器域名」白名单。开发者工具临时关闭「校验合法域名」可绕过，真机必须配。

### 9.5 上传 apk 到应用市场被拒

常见原因：
- 缺少隐私政策声明
- 敏感权限（相机 / 定位 / 读取手机状态）没在 app 内首次使用前弹窗确认
- 应用图标不符合规范（含违禁图样、过于卡通）
- 包名命名冲突（已有人占用）

## 10. 打包前自检清单

- [ ] [configs/env.js](configs/env.js) 的 `APP_ENV_OVERRIDE` 已切到目标环境，**或确认依赖 NODE_ENV 自动推断**
- [ ] `manifest.json` 的 `versionName` / `versionCode` 已自增
- [ ] `manifest.json` 的 `app-plus.distribute.icons` 已配置（不是 dcloud 默认图标）
- [ ] 启动图（splash）已配置（避免黑屏）
- [ ] Android 证书已就位（测试用公共测试证书 / 正式用自有证书）
- [ ] 包名已确认（正式包要稳定，不可后期更换）
- [ ] 后端域名 https 证书有效
- [ ] 小程序：公众平台「服务器域名」白名单已加上目标域名
- [ ] 真机能直连目标 API（浏览器试一下 `https://...`）

## 11. 打包后自检清单

- [ ] **`APP_ENV_OVERRIDE` 改回 `''`**（最容易忘）
- [ ] 包安装到至少 2 台测试机验证（一台老一点的 Android，一台新机）
- [ ] 关键流程冒烟：登录 → 查看专家列表 → 查看课程详情 → 头像上传 → 退出
- [ ] 检查日志没有红色 error（adb logcat）
- [ ] 测试包派发记录（谁、哪个版本、什么时间）
